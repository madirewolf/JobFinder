How to use this

The bot drafts; you submit. Two human-in-the-loop gates between a posting and an actual application — queue (free) and apply (free). Money only flows when you type a CLI command.

Step by step

1

Pull new postings FREE

~weekly. Hits every seeded ATS source (Greenhouse, Lever, Ashby, Workday, etc.). Nothing here calls Anthropic.
jfb ingest all
2

Score the new postings ~$0.01/posting

Four sub-steps. Only the haiku step bills Anthropic; the rest are local (regex + Ollama + cosine math).
jfb classify run         # regex pass        — free
jfb classify embed       # Ollama embeddings — free
jfb classify haiku       # ★ ~$0.01/posting
jfb classify rank        # cosine ranking    — free

# Or chain all four:
jfb classify all
Haiku is only run on rows that don't yet have a fit_score, so re-running is cheap once steady-state.
3

Browse + queue FREE

Open /top and scan by final_rank. Click Queue (curate) on anything worth drafting. Each click inserts an applications row at status='queued' — nothing else. 
jfb web serve --port 8000
# open http://localhost:8000/top
Mode tip: curate never rewrites your master — model only selects projects + pulls verbatim quotes. tailor paraphrases your bullets to match the posting (higher keyword match, higher fabrication risk). Default is curate.
4

Generate drafts ~$0.04/draft

The drafter only acts on rows you queued. Cache tip: batch by mode — the cached system prefix differs between curate and tailor, so alternating per posting pays full price every call. 
jfb draft top --mode curate --limit 5
# ~$0.10 first call + ~$0.03 × 4 cache-hits ≈ ~$0.22 for 5 drafts

jfb draft top --mode tailor --limit 5
# or just one posting:
jfb draft one --posting-id 533 --mode curate
5

Review drafts FREE

Each queued posting now reads review draft. Open it, read the cover letter, emphasis quotes, talking points, red flags. Copy the bits you want; the bot never submits anything externally.
If a draft is bad, re-queue it (resets status='queued') and re-run jfb draft top — within five minutes the cache is still warm, so re-drafts are cheap.
6

Mark as applied FREE

After you've actually submitted on the company's site, click Mark as applied on the posting page. That's the only thing that stamps applied_at. The bot will not assume.

Daily-driver loop

jfb ingest all && jfb classify all      # morning refresh + score (~$0.10–0.50)
jfb web serve --port 8000               # browse, queue 5–10
jfb draft top --mode curate --limit 10  # ~$0.20–0.40 in drafts
# review → submit externally → "Mark as applied"

Tailor vs. curate

tailor curate
What the model writes 3–6 fresh "tailored bullets" paraphrased from your master Just selects which projects to include; pulls VERBATIM quotes from your master
Fabrication risk non-zero — model may round numbers or invent specifics very low — quote-verifier checks every emphasis quote post-hoc
Keyword match per posting Highest (intentional paraphrase) Limited to what your master already says
Cover letter, talking points, red flags LLM-written (both modes) LLM-written (both modes)
Best for Postings where keyword density really matters and you'll review every word Default. Defence-adjacent or any role where truthfulness is high-stakes.

Rules of thumb

How often to run ingest all?Daily or weekly — free.
How often to run classify haiku?Whenever new postings are pending (~$0.01 each).
How often to run draft top?When you've queued 3–10 things and want them drafted at once (cache savings).
Do I have to use both modes?No. Pick curate and stick with it; tailor is the escape hatch.
What if a draft sucks?Re-queue (status='queued') and re-run jfb draft top — cache hit within 5 min.
Cap on daily spend?None enforced. Soft ceiling of 5/day is documented in profile/prefs.md.
Active days expected cost?~$0.30–$1.00 / day. Idle days: $0.
Does the UI ever cost money?No. Browsing and clicking buttons (queue, mark applied, mode toggle) are all free. Only CLI jfb classify haiku and jfb draft * bill Anthropic.

Background-check warnings

Per profile/prefs.md, the bot warns on background-check stringency rather than filtering. Postings always appear in /top; you decide whether to queue them.

  • lenient — apply normally, no warning.
  • moderate — yellow chip + reason ("standard reference / employment verification expected").
  • strict — red chip + explicit reason banner on the posting page.
  • unknown — yellow chip; treated as moderate.
